# Sax Alarm 🎷

Социальный «алкогольный будильник» — Telegram Mini App. Написан по фреймворку SCQA.

**Ситуация.** Люди пьют поодиночке и скучно. **Осложнение.** Никто не напоминает вовремя, а совместность требует координации. **Вопрос.** Как превратить «пора выпить» в игру с друзьями? **Ответ.** Случайный будильник с нарастающими саксофонами, который выключается только доказанным глотком на камеру, сквады с общим множителем и лидерборд самых пьющих.

> Дринком считается любой напиток — вода и кофе тоже. Пей ответственно. 18+

## Как это работает

Бэкенд раз в минуту бросает кость для каждого пользователя внутри его активного окна (ночью не будит). Выпало — в Telegram прилетает пуш «ПОРА ПИТЬ» с кнопкой открытия Mini App. Пользователь жмёт «Проснуться и налить» (это user gesture — легальный запуск звука), саксофоны начинают крещендо через WebAudio GainNode, а камера ждёт доказательство: серию живых кадров, где стакан/бутылка/кружка движется ко рту. TFJS coco-ssd находит сосуд, MediaPipe FaceLandmarker — рот, liveness-проверка требует движения между кадрами. При успехе дринк засчитывается, при двух неудачах доступно ручное подтверждение с пометкой «непроверено». Если друзья из сквада онлайн одновременно, вероятность будильника растёт до ×2 — «пора пить вместе».

## Быстрый старт

```bash
cp .env.example .env            # вписать BOT_TOKEN и MINI_APP_URL
docker compose up -d postgres redis
cd backend && npm i && npm run migrate && npm run dev
cd ../frontend && npm i && npm run dev
```

Тесты антифрода: `cd backend && npm test`.

Аудио: положи зацикленный сакс-трек в `frontend/public/sax-loop.mp3`. Без файла работает синтезированный fallback (WebAudio-«саксофон»: пила + формантный фильтр + вибрато), так что будильник звучит в любом случае.

## Ключевые решения

Звук нельзя запускать автоматически — Telegram и браузеры требуют user gesture. Поэтому цепочка: пуш от бота (работает при свёрнутом приложении) → пользователь открывает Mini App → жмёт кнопку → звук стартует и нарастает. Фото из галереи не принимаются в принципе: в UI нет upload, кадры берутся только из живого `getUserMedia`-потока сериями, сервер проверяет свежесть, pHash-дедупликацию и rate limit. Клиентскому распознаванию сервер не доверяет: для топа лидерборда результат перепроверяется на бэкенде, а участники сквада могут оспорить любой дринк.
